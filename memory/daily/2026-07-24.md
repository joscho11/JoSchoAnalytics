## Draft Board UI

`draft_board_2026.py` now uses the established Weekly Fantasy red-to-green ramp: negative gaps are red, zero is amber, positive gaps are green; rank 1 is green and later positional ranks trend red. The color scale uses the complete ~245-player board and a 95th-percentile absolute-gap cap so filters and one extreme value do not remap or wash out the table. The server-side `Sort by` control is the source of truth and marks its active column with a directional arrow and quiet green surface tint. A header-click sort cannot be reflected as a selected row because Streamlit does not return that state to Python.

## Community Cloud throttle

Uncommitted Draft Board work cannot cause a throttle on the deployed app. The strongest app-side risk found is `page_league_history.py`: any numeric text input immediately starts up to ten seasons of Sleeper history work, including 18 concurrent weekly API calls per season, and both caches are TTL-only. Recommended first mitigation: submit-only form, plausible-ID validation, worker cap around 4–6, and bounded cache entries. Secondary fixes: cache Weekly Fantasy actuals once per season rather than once per week, remove redundant eager imports (nflreadpy/Plotly), and inspect Cloud logs for the banner window. If throttling persists after those fixes, Community Cloud cannot promise fixed CPU; move the public app to a host with reserved capacity.
