## Draft Board UI

`draft_board_2026.py` now uses the established Weekly Fantasy red-to-green ramp: negative gaps are red, zero is amber, positive gaps are green; rank 1 is green and later positional ranks trend red. The color scale uses the complete ~245-player board and a 95th-percentile absolute-gap cap so filters and one extreme value do not remap or wash out the table. The server-side `Sort by` control is the source of truth and marks its active column with a directional arrow and quiet green surface tint. A header-click sort cannot be reflected as a selected row because Streamlit does not return that state to Python.

## Community Cloud throttle

Uncommitted Draft Board work cannot cause a throttle on the deployed app. The strongest app-side risk was `page_league_history.py`: any numeric text input immediately started up to ten seasons of Sleeper history work, including 18 concurrent weekly API calls per season, and both caches were TTL-only. The first code mitigation is now implemented: explicit Load submission; a 15–20 digit numeric plausibility gate; 128 endpoint-cache and 8 history-cache entries; and a 6-worker matchup cap. `page_weekly_fantasy.py` now caches a trimmed season payload (four seasons maximum) and filters locally by week. `page_track_record.py`, the loaded League History chart branch, and the two seasonal-start consumers defer heavyweight imports until their page actually renders. A dependency-free `seasonal_config.py` now owns the shared season-start date, so standalone page rendering no longer relies on `app.py` mutating `sys.path`. CPython 3.11.9 was installed user-scoped and the isolated, ignored `.venv-test` passed `test_fantasy_league_pages.py` (5), `test_betting_pages.py` + `test_site_nav.py` (8), `test_app_draft_board.py` (1), and `test_board_refresh.py` (2). Inspect Cloud logs for the banner window before the manual rename redeploy. If throttling persists after these fixes, Community Cloud cannot promise fixed CPU; move the public app to a host with reserved capacity.
