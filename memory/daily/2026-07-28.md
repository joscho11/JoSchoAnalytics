## Streamlit throttle hot-path fix

Recurring Community Cloud CPU throttling was not explained by user traffic or an app-side
rerun loop. The measured cold-process hotspots were deployment/import work and Help-page
model explanation construction.

Implemented:

- `app.py` now imports a page module only when that page is selected.
- Help model summaries moved to `model_explanations_snapshot.json`; CI checks all 22 source
  artifact hashes, and `scripts/build_model_explanations_snapshot.py` is the intentional
  regeneration path.
- `requirements.txt` now contains only the eight live runtime packages. Removed training,
  deserialization, DFS, and local-helper packages live in `requirements-research.txt`.
- Deploy-parity CI runs the dashboard suites against the exact cloud dependency set.
- Added an all-nine-page offline AppTest guard.

Measured:

- Help model-summary path: 7.551s wall / 1.766s CPU before; 0.000285s wall / ~0 CPU after.
- Default cold AppTest: 4.589s wall / 0.891s CPU before; 0.633s wall / 0.547s CPU after.
- Clean minimal-runtime validation: 51 passed; targeted local validation: 15 passed; all
  nine pages rendered cleanly.

No model, tracker, or projection-result artifact changed.
